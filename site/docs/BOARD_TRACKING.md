# 확인·추적과 일정 보드

- `확인`은 해당 항목 ID를 영구 숨김 처리한다. 일정 revision이 바뀌어도 다시 나타나지 않는다. 기존 resolved/dismissed 기록도 확인으로 해석한다.
- `추적`은 같은 일정 ID의 현재 레코드를 사용한다. 날짜·제목·취소 상태와 revision이 갱신되며 기존 중복 조건이나 검토 조건이 사라져도 추적 목록을 유지한다. 갱신은 화면 60초/포커스 복귀, 푸시는 기존 수집 주기를 따른다. 수정이 아직 소스에서 수집되지 않았거나 새 ID로 별도 생성된 일정은 자동 연결하지 않는다.
- 추적 버튼을 다시 누르면 현재 revision을 확인한 기준으로 저장하고 추적을 계속한다. 확인 버튼을 누르면 추적 목록에서도 숨긴다. 기존 의견·처리 이력은 보존하되 편집 UI는 제거했다.
- 변경 항목은 revision별 여러 카드 대신 일정별 최신 카드로 모은다. 확인 상태는 확인함·알림·MCP·푸시와 대시보드 확인 필요 영역에 반영한다.
- API 저장은 사용자 범위 및 version 비교를 유지한다. 기존 change ID는 다음 쓰기 때 안정적인 일정 ID로 정규화한다. DB 스키마 변경은 없다.

## 화면

[Linear Board layout](https://linear.app/docs/board-layout)을 Aside REPL로 확인하고 공개 보드 이미지·문서의 상태 열, 카드 정보 순서, 가로 스크롤 구조를 검토했다. 로그인된 Linear 앱의 내부 소스 코드를 가져온 것은 아니다. [Asana Timeline](https://help.asana.com/s/article/managing-tasks-and-dependencies-with-timeline)의 시간축과 겹침 표현을 참고했다.

확인함은 확인할 항목/추적 중 두 열. 일정 화면은 간트/보드 전환을 제공한다. 간트는 고정 제목 열과 시간 막대를 분리하고 사람별 접기를 제공한다. 보드는 제안/확정/완료/취소 열과 제목/날짜/참여자 순으로 구성한다. 카드 이동으로 원본 일정 상태를 수정하는 기능은 제공하지 않는다. 업무 파랑, 크라임씬 보라, 개인 청록과 텍스트 라벨을 함께 사용한다.

## 검증

TypeScript 및 production build, 확인 후 revision 변경에도 숨김, 추적 중 조건 해소·취소·제외, 기존 처리 상태 호환, 사용자 격리·저장 충돌·의견 보존 검증. Aside에서 합성 데이터의 데스크톱 간트/보드 전환과 390px 모바일 레이아웃을 확인했다. 실데이터에 임의 확인·추적 기록은 만들지 않았다.
