# 보드·달력 UI 검토 — 2026-11-01

## 실제 서비스 확인

- 사용자 요청에 따라 Notion 개인 영역에 별도 UI 검토 페이지와 일정 데이터베이스를 생성했다. 합성 일정 4개만 넣었으며 실제 수집 데이터는 복제하지 않았다.
- 상태별 보드와 날짜별 달력을 실제로 생성한 후 Aside에서 렌더링과 DOM 스타일을 확인했다.
- 관찰한 보드 카드 폭은 260px, 그룹 폭은 276px였다. 긴 제목은 줄바꿈하고 분류·날짜·참여자 속성을 아래에 배치한다. 모아는 이 구조를 밝은 중립색 화면에 적용했다.
- 로그인된 Google Calendar 월간 화면을 읽기 전용으로 확인했다. 오늘 표시, 종일 일정 막대, 시간 일정 점 표시와 넘침 처리를 참고했다.

## 적용

- 보드와 카드: 흰 카드, 가는 테두리, 작은 상태·분류 라벨, 제목 우선 배치. 모바일 보드는 가로 스크롤을 유지한다.
- 달력: 월요일 시작, 실제 월에 맞는 행 수, 오늘 표시, 선택 날짜 상세 목록. 모바일은 점 표시와 아래 상세 목록을 사용한다.
- 모든 페이지의 예시 버튼과 데모 표시 경로 제거.
- 별도 설정 탭에 기기별 푸시 토글과 수집 연결 진입점 배치. 초기 상태 확인 실패를 꺼짐으로 표시하지 않는다.
- 기존 확인·추적과 필터 저장 계약을 유지한다.

## 검증

- TypeScript 검사 및 배포 빌드 통과.
- Node 테스트 파일 4개 통과: 확인·추적, 날짜 경계, 간트 배치, 달력 경계.
- 달력 검증에는 윤년, 4/6주 월, 서울 날짜 변환, 자정 경계, 종일 종료일 제외가 포함된다.
- 기존 간트 테스트의 Node 직접 실행을 위해 내부 import에 `.ts` 확장자를 명시했다.
- 비공개 Sites 배포 성공, MCP 유지. source: `b59763ab77e2720f18eef9249b1bb8246ac9ae34`.
- 실사이트 대시보드·보드·월간 달력과 390px 모바일 배치를 확인했다. 설정 토글은 기존 등록 상태를 읽어 켜짐으로 표시했다. 이번 검증에서는 실제 알림 구독 변경이나 푸시 수신 재시험을 하지 않았다.
- 테스트 Notion 페이지 및 개인 일정 스크린샷은 공개 플러그인 패키지에 포함하지 않는다.
