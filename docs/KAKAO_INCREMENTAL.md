# 카카오톡 이어 읽기

`hub.sources.kakao_incremental.KakaoScan`은 호스트 컴퓨터 유즈의 화면 관찰·스크롤과 공통 선별 저장을 연결한다. 독립 GUI 데몬은 아니다. `run_scan`은 ComputerDriver의 `open_latest`, `observe_pair`, `scroll_older`를 호출하는 실행 루프다. Codex 도구 호스트는 아래 CLI로 같은 상태 전이를 실행한다.

## 실행

실제 설치의 카카오톡 DB를 `HUB_DB`로 지정한다. 기본 DB와 운영 DB를 혼동하지 않는다. JSON은 stdin으로 전달하고 원본 AX·본문을 로그나 저장소에 남기지 않는다.

1. 방 목록에서 조용한 채팅방·비활동 제외와 계정 범위 target을 확인한다. `kakao-scan-start`에 `target,label,since,until,quiet,latest,max_pages`를 전달한다. 날짜는 timezone 포함 ISO, 기본 max_pages는 80이다. 최신 화면부터 시작한다.
2. 실제 방 제목을 재확인하고 두 번 독립 관찰한다. 각 화면은 오래된 순서부터 행을 배열한다. 로컬 검토 후 `kakao-scan-step`에 `target,label,quiet,latest,observations,externalProcessingAllowed:true,atLatest`를 전달한다. 첫 화면만 atLatest가 true다. 행 형식은 `kakao-reviewed`와 같다. 작성자·발언 일시를 추측하지 않는다. 재개 중에는 start가 반환한 기존 since/until을 적용한다.
3. `action:scroll-older`면 **실제 화면에 연속 3개 이상 메시지를 겹치게** 과거 방향으로 스크롤한 후 2를 반복한다. 화면이 변했는지 다시 확인한다. 임의 좌표를 영구 저장하지 않는다.
4. `action:restart-latest`면 미완료 과거 구간을 메운 것이다. start를 다시 호출하고 최신 화면부터 신규 메시지까지 반영한다. `stop`이면 반드시 순회를 종료한다.
5. `sourceEnd:true`는 앱의 명시적인 대화 시작을 확인했을 때만, `rangeEnd:true`는 지정 시작일에 도달한 실제 날짜 증거가 있을 때만 보낸다. 로딩 실패·빈 화면·스크롤 무변화로 설정하지 않는다. 캡처가 불안정하면 완료 대신 재검토한다.

`kakao-scan-status`는 target을 받아 별도 저장된 상태를 반환한다. 해당 상태에는 해시만 있고 본문·화면 좌표는 없다. CLI에는 사용자 지정 모델의 `provider`도 전달할 수 있다. 외부 전송 동의는 step마다 확인한다.

## 저장과 재개

- `head`: 이번 순회의 최신 화면. `baseline`: 이전 **완료된** 순회의 최신 경계. `frontier`: 이번 미완료 순회에서 저장까지 성공한 마지막 화면.
- 미완료 실행을 재시작하면 frontier를 찾는 `seeking` 모드다. 탐색 화면은 모델 호출·본문 저장 없이 비교한다. 찾으면 그 페이지를 재확인하고 과거 방향을 계속 읽는다. 탐색 중 지나친 최신 메시지는 완료 후 최신 화면 재방문으로 처리한다.
- 완료된 실행의 다음 순회는 최신 화면부터 수집하고 baseline의 유일한 연속 3행과 일치하면 멈춘다. 같은 화면의 신규 메시지도 먼저 저장한다.
- 모든 저장 배치 성공 뒤 frontier를 기록한다. 도중 실패하면 전진하지 않는다. 저장 직후 체크포인트 쓰기 전에 종료되어도 한 페이지 재처리만 발생하며 멱등 저장을 적용한다.
- 화면 사이 겹침 누락, 날짜/검토 미확인, 반복 문구의 모호한 일치에서는 정지한다. 의도적으로 제외한 행은 None 간격을 유지하며 연속 앵커를 만들지 않는다. 충분한 안전한 앵커가 없는 방은 자동 완료할 수 없다.
- 2회 연속 화면 정체, 페이지 예산, 취소를 별도로 보고한다. Python 실행 루프는 기본 180초 예산도 적용한다. 드라이버 자체 호출에도 호스트 timeout을 적용해야 한다.
- 모델 보존 규칙 변경·범위 확장은 기존 완료 경계를 무효화한다. 기간 축소는 기존 완료 경계를 재사용할 수 있다. 계정 변경은 별도 target을 사용한다.

## 기존 데이터와 한계

기존 `kakao_windows`, `kakao_anchor_history`, `hostObservationOnly`는 위치 관찰/중복 판별용이다. 저장 성공·전체 연속 범위 완료의 증거가 없으므로 새 체크포인트로 자동 승격하지 않는다. 최초 전환은 범위를 확인하는 순회가 필요하며 기존 메시지는 기존 발생 키로 중복 저장을 방지한다. 새 상태가 만들어진 이후부터 위 재개/중단 흐름을 사용한다.

완료 경계보다 오래된 수정 메시지를 자동 감지하는 기능은 아니다. 과거 수정 확인은 별도의 제한 재검사 대상이다. 메시지 삭제·대화 부재를 추론하지 않는다. 실제 운영 DB에 새 수집을 실행한 것과 합성 드라이버 검증을 구분한다.

검증: 완료 경계 중단, 동일 화면 신규 메시지, 프로세스 재시작, 탐색 중 모델 호출 0, 저장 실패, 공백, 앵커 유실, 화면 정체, 대상 격리, 드라이버 루프를 합성 데이터로 시험한다. 실제 카카오톡 GUI에서의 새 루프 파일럿은 별도 수용 검증이다.
