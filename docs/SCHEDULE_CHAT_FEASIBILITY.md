# 일정 채팅 도입 검토

2026-11-01. 최초 요청은 가능성 검토이며, 후속 승인으로 OpenAI 호환 키 재발급과 합성 도구 호출 시험까지 완료했다. 후속 요청으로 REA 기반 채팅 UI와 제한된 도구 실행기를 구현했다. 최신 상태는 SCHEDULE_CHAT_IMPLEMENTATION.md를 따른다.

## 후속 실호출 검증

- 사용자가 기존 키 폐기·재발급을 승인했다. 기존 OpenAI 호환 키를 폐기하고 `Moa Schedule Chat` 키를 발급했다. Anthropic 키는 유지했다.
- 새 키는 Git에서 제외된 로컬 `.runtime/secrets`에 디렉터리 0700, 파일 0600으로 보관했다. 브라우저 파일 전달본은 이동 후 제거했으며 키 원문을 문서·소스·로그에 출력하지 않았다. 아직 Sites 서버 비밀 설정에는 등록하지 않았다.
- `gpt-5.4-mini`로 `/v1/chat/completions`에 `tools`와 `tool_choice: auto`를 전달했다. 합성 일정 질문에 `schedule_lookup` 함수 호출을 반환했고 날짜 인수 `2030-01-02`를 검증했다.
- 같은 `tool_call_id`로 `role: tool` 결과를 반환한 두 번째 요청이 성공했다. 모델은 도구 결과에만 있던 합성 장소와 시간을 답변에 반영했다.
- HTTP 200 두 번, 1.76초 + 0.91초, 응답 usage 합계 557토큰. 단일 합성 시험이며 운영 성능·요금·모든 모델의 호환성을 보장하지 않는다.
- 따라서 이 모델/엔드포인트에서 **함수 도구 자동 선택 → 인수 생성 → 결과 반환 → 최종 답변**은 검증됐다. 실제 DB 수정, 스트리밍 도구 호출, 원격 MCP 직접 연결, strict 스키마의 전체 강제 보장은 아직 미검증이다.
- 재현: `python3 scripts/probe-codyssey-tools.py --key-file <로컬 키 파일> --model gpt-5.4-mini`. 유료/할당량 사용 가능성이 있는 명시적 실호출 스크립트이며 자동 테스트에는 포함하지 않는다. 실제 일정이나 외부 쓰기 도구는 사용하지 않는다.

## 결론

모아 안에 ChatGPT 형태의 전용 채팅 탭을 두고, 모델이 제한된 일정 도구를 요청하며 서버가 실행하는 구조는 구현 가능하다. Codyssey 게이트웨이의 기본 함수 도구 호출은 위 합성 시험으로 확인했다. 스트리밍은 추가 시험 대상이다. ChatGPT 대화방을 삽입하는 것이 아니라 자체 대화 UI와 서버 실행기를 만든다.

## 직접 확인한 API 문서

Aside의 로그인된 https://usr.codyssey.kr/public-api-console 문서·키 관리 화면을 직접 확인했다.

- Public API Base URL: `https://copa.codyssey.kr`.
- OpenAI Base URL: `https://copa.codyssey.kr/v1`.
- 문서에 OpenAI `/v1/chat/completions`, `/v1/models`, Anthropic `/v1/messages`, `/v1/messages/count_tokens`, `/v1/models`가 있다.
- 인증 예제는 Bearer virtual-key이다. Cursor·Continue·Claude Code 연결 예제가 제공된다.
- 문서상 채팅 모델에 `gpt-5-mini`, `gpt-5.4-mini`(차감 배수 0.5), `gpt-5.4`(1), `gpt-5.5`(2), Gemini·Claude 모델이 있다. 실제 모델 가용성·출력 품질은 아직 실호출 미검증이다. 이 배수는 표시된 토큰 차감 배수이며 현금 가격으로 환산하지 않는다.
- OpenAI·Anthropic 호환 키를 각각 1개만 발급할 수 있다. 최초 검토 시 두 종류의 기존 키가 있어 발급 버튼이 비활성화돼 있었다. 후속 승인에 따른 재발급 결과는 위에 기록했다.
- `tools`, `tool_choice`, 스트리밍, 구조화 출력, 원격 MCP, 최대 문맥, rate limit, 개인정보 보관 정책에 대한 상세 계약은 이 콘솔 문서에서 확인되지 않았다. OpenAI 호환이라는 이유만으로 지원을 보장하지 않는다.
- Responses/Decisions 엔드포인트는 확인한 목록에 없다. 기존 Decisions 분석 공급자는 교체하지 않고 채팅 공급자를 별도로 둔다.

## 권장 구조

`채팅 탭 → 인증된 /api/chat → ChatProvider → 제한된 도구 실행기 → 공통 일정 서비스 → 기존 D1`

- CodysseyOpenAIAdapter를 첫 구현으로 두고 공급자·모델·base URL을 설정으로 교체한다. 모델별 tools/streaming/structured-output capability를 기록한다.
- 우선 `gpt-5.4-mini`를 파일럿 후보로 사용한다. 실제 지연·오류·도구 호출 정확도를 확인한 뒤 고정한다. 복잡한 충돌 해석에 상위 모델 사용은 별도 정책으로 제한한다.
- 자체 채팅에서는 같은 서버의 일정 서비스를 직접 실행한다. 세션 인증을 외부 모델에 전달하거나 외부 모델이 DB/SQL을 직접 실행하도록 하지 않는다.
- 외부 Dot/ChatGPT에는 같은 도구 스키마와 서비스 함수를 기존 MCP로 노출한다. 원격 MCP를 모델 공급자가 직접 지원하지 않아도 서버가 function calling 도구를 실행하는 방법으로 연결할 수 있다.
- 조회 결과에는 일정 ID·날짜·출처·마지막 반영 시각을 붙인다. '저장된 일정에서 겹침 없음'과 '실제로 비어 있음'을 구분한다.

## 기존 구현과 추가해야 할 도구

현재 MCP는 `schedule_status`, `schedule_list`, `schedule_attention`, `schedule_apply_delta`를 제공한다. 확인/추적 쓰기는 UI의 `/api/attention`에 있으며 MCP 전용 변경 도구는 아직 없다.

| 도구 | 역할 | 구현 방향 |
| --- | --- | --- |
| schedule_search | 기간·사람·종류·제목으로 조회 | 기존 조회 확장, 기간 겹침·종일 종료일·미정 일정 지원 |
| schedule_get | 한 일정의 상세·근거·변경 이력 | 필요한 근거만 가져오기 |
| schedule_attention | 겹침·확인·추적 후보 조회 | 기존 공통 함수 재사용 |
| schedule_review_set | 확인 또는 추적, 의견 저장 | 기존 API 쓰기를 공통 서비스로 추출, MCP와 채팅 공유 |
| schedule_propose_change | 날짜·상태 등 변경안 작성 | 실제 쓰기 없이 대상·전후 값·현재 버전 제시 |
| schedule_apply_change | 사용자가 승인한 변경안 반영 | 서버 검증, 버전 확인, 멱등성, 감사 이력 |

수집기용 `schedule_apply_delta`를 대화 모델의 일반 편집 도구로 노출하지 않는다. 설치 ID와 sequence를 모델이 만들어 수집 상태를 훼손하지 않게 한다.

## 상태 변경과 동기화

- 확인/추적은 현재 사용자 기록을 그대로 사용한다. 분명한 사용자 명령은 불필요한 반복 확인 없이 실행하고 결과를 보여준다.
- 날짜·취소·일정 제외 등 영향 있는 편집은 대화 내 전후 비교와 적용 버튼으로 처리한다. 모호한 일정명은 후보를 좁힌다.
- 사람이 변경한 날짜/상태는 수집 원본과 별도의 override로 저장한다. 새 수집이 이를 덮어쓰지 않으며 원본과 충돌하면 확인함에 올린다. 원본 복원도 제공한다.
- 최초 범위는 모아 내부 상태 관리다. Google Calendar 원본 수정·메일/채팅 발송은 별도 권한과 명시적 제품 요구가 필요한 후속 단계다.

## 저장·비용·보안

- 기존 D1을 유지한다. 대화·메시지·도구 실행 기록은 owner/session과 안정된 ID로 증분 저장한다.
- 현재 readData는 사용자 전체 sync_records를 읽는다. 채팅은 모든 일정을 매번 프롬프트에 넣지 않고 기간·인물·분류별 검색 서비스와 인덱스가 있는 조회용 projection을 추가한다. delta 적용 시 바뀐 일정만 갱신한다.
- 최근 대화와 요약을 사용하고 필요할 때만 상세 근거를 조회한다. 도구 결과 개수·본문 길이·호출 횟수·총 토큰·시간 제한을 둔다. 초기 도구 루프 상한 4회는 파일럿에서 조정한다.
- 키는 서버 비밀 설정에 보관하고 브라우저·Git·MCP 응답·대화 기록에 넣지 않는다.
- owner는 인증 세션에서 주입하며 모델 인수로 받지 않는다. 허용 도구만 실행하고 임의 URL·SQL·셸을 허용하지 않는다.
- 수집한 메시지와 도구 결과는 데이터로 취급한다. 거기에 포함된 지시문으로 도구 권한을 확대하지 않는다.
- 실제 일정과 근거 일부가 Codyssey 및 선택한 모델 공급자에게 전달된다는 흐름을 설정 화면에 명시한다. 보관 정책은 실제 연결 전 추가 확인 대상이다.

## 구현 순서와 수용 기준

1. 기존 키를 안전한 서버 설정으로 재사용할 수 있는지 확인한다. 키가 없다면 기존 사용처를 확인하고 재발급 여부를 결정한다. 새 키 발급을 위해 기존 키를 임의 폐기하지 않는다.
2. 합성 데이터로 일반 채팅, 한국어 답변, tools 왕복, 스트리밍/취소, 401/429/시간초과, 사용량 보고를 시험한다. 비지원 기능은 capability로 명시하고 거짓 성공 처리하지 않는다.
3. 조회 전용 채팅: 내일/이번 주/크라임씬/중복 약속 질문에 실제 근거를 연결한다. 제목·인물·날짜를 꾸며내지 않는지 확인한다.
4. 확인/추적 도구: 최신 버전 확인, 재시도 중복 방지, 타 사용자 접근 차단, 기존 UI 즉시 반영을 검증한다.
5. 변경안/override: 적용 전후 비교, 수집 후 보존, 동시 변경 충돌, 복구를 검증한다.
6. 작은 실제 범위로 지연·토큰·도구 정확도 측정 후 비공개 배포한다. 성능 수치는 아직 없다.
