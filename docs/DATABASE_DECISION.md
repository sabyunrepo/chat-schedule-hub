# DB 설계 결정

2026-11-01. 결정: 기존 로컬 SQLite와 Sites 제공 D1을 사용한다. 별도 PostgreSQL/Supabase는 추가하지 않는다.

## 현재 확인한 구현

- `hub/core.py`: SQLite WAL, 외래키, 원본 메시지 식별 UNIQUE, revision UNIQUE, 처리 큐, 수집 경계, 변경 이력과 outbox가 있다.
- `site/.openai/hosting.json`: Sites D1 `DB` 바인딩이 선언되어 있다. `site/db/index.ts`가 바인딩을 사용한다.
- `site/db/schema.ts`: snapshots, preferences, pairings가 있다. 사용자·탭별 필터는 복합 기본키로 격리하고 버전 조건으로 동시 수정을 감지한다.
- 현재 `/api/sync`는 소유자별 전체 JSON 스냅샷을 저장한다. 설치 ID와 증가 sequence로 오래된 전송의 덮어쓰기를 막는다. `/api/data`는 전체 스냅샷을 반환한다.
- 로컬 전송 한도는 900,000바이트다. 변경분 전송, 기간·인물 SQL 조회, 착오 검토 의견 테이블은 아직 구현되지 않았다.
- 이 문서는 소스와 제공 스토리지 계약 확인 결과다. 현재 배포 DB의 실데이터 규모·지연·장애복구를 실측한 결과는 아니다.

## 역할 분리

| 위치 | 저장할 데이터 | 이유 |
|---|---|---|
| 로컬 SQLite | 수집 지점, ID·지문, 재시도, 선별 근거·수정 이력, 판단 캐시, outbox | 네트워크 없이 원자적 저장·중복 제거·재개 가능 |
| Sites D1 | 선별된 일정·인물·출처 정보, 사용자 필터, 향후 착오 후보·의견·처리 이력 | 기기 간 조회와 사용자 입력의 지속 보관 |
| 저장하지 않음 | 무관 메시지 본문, 봇 토큰과 모델 키의 Site 전송 | 선별 수집 계약 유지 |

D1을 봇 Gateway 실행 환경으로 사용하지 않는다. 봇은 로컬 프로세스에서 실행하고 인증된 Site API로 동기화한다. DB는 AI 입력량을 자동으로 줄이지 않는다. 안정적인 메시지 키·의미 revision·판단 버전 기반 캐시가 동일 입력의 재판단을 줄인다.

## 전체 확대 전 구현 순서

1. 봇 작업 큐를 SQLite에 통합한다. allowlist 확인 후 ID·종류·수정 시각·재시도 시각만 저장하고 본문은 선별 후 보관한다. 실제 수정은 재판단하고 동일 revision은 중복 처리하지 않는다.
2. Sites에 일정 행과 참여자 연결을 추가하고 기존 스냅샷과 호환하는 버전별 동기화 API를 만든다. 최초 동기화는 페이지로 나누고 이후 outbox의 변경분만 보낸다. 삭제·취소도 명시적으로 전달한다.
3. 수신 ACK에는 적용한 작업 ID/version을 담는다. 원자적 반영 후 ACK하며, 로컬은 정확히 확인된 항목만 완료 처리한다. 응답 유실 시 재전송해도 중복되지 않아야 한다. sequence만으로 늦은 배치를 버려 누락시키지 않는다.
4. 기간·인물 필터와 커서 페이지네이션을 서버 조회에 적용한다. 소유자와 시작 시각/ID, 참여자와 일정 키를 기준으로 인덱스를 설계하고 EXPLAIN QUERY PLAN으로 확인한다. 기간 겹침 조회는 시작·종료 조건을 함께 검증한다.
5. 착오 후보와 사람의 의견·처리 상태를 별도 테이블로 분리한다. 수집 동기화는 사람의 기록을 덮어쓰지 않는다. 새 근거는 기존 처리 이력을 보존하면서 재검토 대상으로 만든다.
6. Sites 스킬의 소스·마이그레이션·배포 절차로 변경한다. 이미 적용된 migration은 수정하지 않는다. 구형 클라이언트 전환과 초기 데이터 이관을 검증한 뒤 스냅샷 경로를 제거한다.

## 수용 기준

- 같은 수신 배치를 반복해도 일정·의견 중복 0, 응답 유실/중단 후 재개 시 누락 0.
- 수정 메시지의 기존 근거 이력 유지, 영향받는 일정만 갱신. 신규 메시지가 없어도 수정 이벤트 처리.
- 사용자 격리, 서로 다른 기기의 필터 복원 및 동시 수정 충돌 검증.
- 합성 1천/1만 일정으로 전송 바이트·DB 조회 시간·반환 행 수를 비교한다. 실데이터 파일럿 수치와 구분한다.
- 변경 없음은 모델 호출 0을 목표로 검증하고, 변경분 전송량이 전체 데이터 크기에 비례하지 않는지 확인한다.
- 한 채널·스레드 파일럿까지 기존 스냅샷을 허용한다. 전체 확대는 위 동기화 및 실제 수집 검증 이후다.

## 재검토 조건

여러 수집 worker가 동시에 동일 큐를 공유해야 하거나, 실측으로 SQLite/D1의 용량·쓰기·조회 제한에 도달할 경우에만 별도 서버 DB를 검토한다. 파일 저장이 필요해지면 Sites R2를 검토하되 현재는 추가하지 않는다. 현재 요구에는 별도 DB의 운영·인증·네트워크 비용을 늘릴 근거가 없다.
