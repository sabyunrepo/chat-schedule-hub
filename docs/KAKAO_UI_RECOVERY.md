# 카카오톡 UI 제어와 재개

호스트의 컴퓨터 유즈 전용 절차다. 플러그인이 cua_repl을 독립 데몬으로 실행할 수 있다는 뜻은 아니다.

## 검증한 복구 경로

접근성 요소 기반 스크롤에서 `AXError.noValue`, `windowNotFoundAtPosition`, `Computer Use is not active`가 관찰됐다. 앱 내부 스크롤은 화면에서 확인한 좌표를 사용했을 때 연속 3회 성공했다. 전후 스크린샷에서 다른 카드가 나타났고 스크롤 위치는 0.139489→0.133461→0.127433→0.121404로 변했다. 각 동작과 관찰은 약 2~4초였다. 호스트 내부 오류 자체가 수정된 것은 아니다.

1. GUI 조작자는 한 명만 둔다. 위임에서 직접 수행으로 바꿀 때 기존 작업자를 먼저 중단한다.
2. `cua.getApp('KakaoTalk')`로 연결하고 전체 AX와 스크린샷에서 방 제목·대화 영역·창 크기를 확인한다.
3. 신선한 요소 번호로 한 번 스크롤한다. 요소 오류가 발생하면 재연결 후 스크린샷에서 확인한 **대화 본문 안의 좌표**로 한 번 재시도한다. 입력창·카드 링크·참석 버튼은 클릭하지 않는다.
4. 좌표는 관찰된 창에서만 유효하다. 다른 창·크기·대상 변경, 사용자 포커스 변경 시 재관찰한다. 테스트 좌표를 설치자의 기본값으로 넣지 않는다.
5. 한 호출은 작은 스크롤 한 번과 후속 관찰만 수행한다. 긴 스크롤 루프는 시간 초과 후 실행 위치가 불분명해진다. 최초 복구는 전후 스크린샷으로 실제 움직임을 확인한다.
6. 이후 전체 AX를 정규화해 비교한다. 요소 번호·읽지 않은 사람 수만 바뀐 것은 진행이 아니다. 스크롤 위치만 바뀌고 내용이 같으면 같은 구간이다. 큰 카드 때문에 3행 겹침이 없으면 이동량을 줄이거나 확인 관찰을 추가한다.
7. 오류나 대상 변경 때 저장 커서를 전진시키지 않는다. 이전 화면의 의미적 지문·보존 근거를 사용해 다시 위치를 찾는다. 스크롤 막대 수치는 로딩 때 변하므로 영구 커서로 사용하지 않는다.

## 정규화·저장

발언 시각은 `Value: 오전 9:23` 및 읽음 수 다음 줄의 시각 형식을 모두 처리한다. AX 요소 번호는 탭 들여쓰기가 있는 요소 행에서만 제거한다. 메시지 본문의 `17`, `6 12 13` 같은 숫자와 빈 줄은 후보 날짜일 수 있으므로 그대로 보존한다. 메타데이터 시각의 이어지는 줄은 본문에 섞지 않는다.

## 원본에서 사라진 과거 대화

`지난 대화 보기`를 눌렀을 때 카카오톡이 대화를 불러올 수 없다는 안내를 표시할 수 있다. 실제 확인된 안내는 미확인 대화를 서버에 3일 보관 후 삭제하며 오픈채팅은 톡클라우드 백업 대상에서도 제외된다고 설명했다. 이는 스크롤 재시도로 해결된다고 보장할 수 없는 원본 공백이다. 방·관찰 시각·경계·안내 종류를 비공개 상태에 기록하고 해당 기간은 미완료로 남긴다. 더 오래된 로컬 조각이 보이더라도 중간 공백이 복구된 것은 아니다.

## 수집 입력

`hub.sources.kakao_ui.parse_window`는 실제 전체 AX 관찰의 대화 표만 파싱한다. 카드 속 모임 시간을 발언 시각으로 사용하지 않으며, 불명확한 작성자/발언 시각은 null이다. `progress`는 화면 내용 변화만 평가하고 저장 체크포인트를 전진시키지 않는다.

`python3 -m hub.cli kakao-observe`는 JSON stdin으로 아래 필드를 받는다. 실제 대화는 공개 예제나 로그에 넣지 않는다.

- target, label: 검증한 방의 고정 로컬 키와 정확한 창 제목
- observations: 독립적으로 관찰한 전체 AX 문자열 2개. 같은 관찰을 복사해서 2개로 만들면 안 된다.
- quiet: 보관함 제외를 확인한 boolean. 미확인인 경우 본문을 가져오지 않는다.
- latest, since, until: 시간대 포함 ISO 날짜. 방 목록의 날짜와 메시지 발언 시각은 별개다.
- externalProcessingAllowed: 사용자 설정에 따라 명시적으로 true일 때만 Decisions 전송

원본 ID가 없는 관찰은 고유 연속 3행으로 발생 키를 확인한다. 날짜 미확인·모호한 반복·누락 답글은 보류한다. 새 관찰은 새 batchId이며 동일 내용 재시도는 캐시를 사용한다. 과거 구간까지 연속적으로 확인하지 못하면 partial로 남긴다. UI 제어 복구, 선별 저장, 전체 기간 완료, 일정 동기화를 각각 보고한다.
