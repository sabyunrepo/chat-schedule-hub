# 선택 수집 파일럿 — 2026-11-01

상태: 소규모 검증 완료, 전체 수집 보류. 개인 원문·계정·서버 식별값은 이 보고서에 포함하지 않는다.

## 범위와 방식

사용자가 지정한 Discord 서버의 한 채널에서 컴퓨터 유즈 접근성 트리를 읽었다. 최초 렌더링된 메시지 30개 중 텍스트 27개를 선별 저장에 전달했다. 이미지/GIF 3개는 해석하지 않았고 미수집으로 남겼다. 겹침 스크롤 두 번을 수행했고 두 번째 스크롤에서 과거 메시지 20개가 추가로 렌더링되는 것을 확인했다. 이 추가 구간을 포함한 전체 기간 수집 완료를 뜻하지 않는다.

원문 ID는 이 접근성 경로에서 확인하지 못했다. 파일럿 텍스트는 겹치는 화면에서 작성자·시각·본문을 대조한 발생 키를 썼다. 같은 분의 반복 메시지와 수정 전후 동일성은 일반적으로 보장하지 못하므로 전체 확대 조건을 통과하지 않았다. 폴더 내 수집기는 호스트가 관찰 배치를 제공하는 구조이며, 이 측정에서 관찰 결과 정규화는 Codex가 수행했다. 무인 수집 처리량 측정이 아니다.

## 측정

| 구간 | 실측 |
| --- | --- |
| 접근성 화면 읽기 | 543ms, 1회 |
| 스크롤 + 새 화면 읽기 | 1,550ms / 1,594ms |
| 초기 6종 의도 분류 | 27개 / 1,954ms, 본문 27개 보관 |
| 관련성 predicate + 의도 choice | 동일 27개 / 한 요청에 54개 질문 |
| 최종 API 지연 3회 | 494.78 / 537.53 / 704.86ms |
| API 중앙값 | 537.53ms |
| 최초 선별·DB 저장 | 498.33ms (첫 API 포함) |
| 동일 페이지 재처리 | 2.20ms, API 0회, 캐시 27개 |
| 보관 본문 | 16개 / 27개 (11개 제외) |
| 직렬화 메시지 본문 포함 payload | 7,451 → 4,432 bytes, 약 40.5% 감소 |
| 수작업 검토 필수 시간·참여 단서 | 12개 중 12개 보관 |

동일 입력을 반복 호출한 작은 표본이며 서버/프롬프트 캐시 영향을 분리하지 않았다. 일반적인 처리량·정확도·비용 보장으로 해석하지 않는다. 화면 조작과 수동 정규화, 에이전트 조율 시간은 API 지연에 포함하지 않는다. 지문·분류·SQLite 인덱스 때문에 DB 파일 전체가 40% 작아진다는 뜻은 아니다. 선별 판단 자체에는 관찰 텍스트를 OpenAI로 보내며, 줄어드는 것은 지속 저장과 후속 추출·동기화 입력이다.

## 발견과 변경

첫 분류는 불확실 응답과 인접 문맥을 모두 보존해 저장량을 줄이지 못했다. 관련성 판단을 의도와 분리한 뒤 불필요한 잡담을 제외했다. 다만 종료 시간 단서를 모델이 무관하다고 판단한 사례가 있어 명시적 시간·날짜·취소·참여·예약 등의 단서를 보존하는 보완 규칙을 추가했다. 키워드만으로 메시지를 버리지 않는다.

일정 관련성이 0.1을 넘거나 명시적인 시간·일정 단서가 있으면 보관한다. 관련성이 0.6 이상이면 10분 이내의 앞뒤 메시지도 보존한다. 이미 저장된 일정 근거는 재판정으로 삭제하지 않는다. 모델 추정치는 보정된 확률을 보장하지 않으며 임계값은 추가 표본 검증 대상이다.

무관 본문은 지문·분류 결과만 남긴다. 비교용 전체 원문 DB는 측정 후 제거했고, 최종 선별 파일럿 DB는 프로젝트 외부의 사용자 앱 데이터 폴더에 둔다. 실제 대화나 파일럿 일정은 공개 저장소·Sites에 업로드하지 않았다.

## 확대 전 남은 조건

- 원본 ID 확보 또는 반복 메시지·수정 메시지의 안정적인 발생 식별 검증
- 페이지 경계를 넘는 짧은 응답, 답글, 모임 변경·전체 취소·개별 불참의 실데이터 검증
- 이미지·GIF·스레드의 미수집 표기 및 필요한 자료의 처리 정책
- 동일 방의 더 큰 표본에서 누락 검토, API 비용과 지연 분포 측정
- 카카오톡 한 방에서도 동일 계약 검증

소프트웨어 회귀 검증은 20개 테스트 통과. 웹앱 타입 검사·빌드 통과, 로컬 실제 Chrome에서 슬로건 제거·예시 버튼·일정 표시를 확인했고, 실제 비공개 배포 URL에서도 기능명 중심 화면을 확인했다. 모바일 실기기 검증은 별도다.

[Decisions 공식 문서](https://developers.openai.com/api/docs/guides/decisions)의 다중 질문과 이름 기반 응답 매핑을 사용한다.


## 추가 파일럿: 카카오톡과 Discord 스레드

카카오톡 일반 대화방 한 곳에서 최근 비금융 텍스트 12개를 시험했다. 결제 카드와 초대 링크 본문은 분류 입력에서 제외했다. 접근성 읽기 8,752ms, 위로 한 페이지 스크롤 후 읽기 9,169ms, 스크린샷 8,802ms였다. 스크린샷 전환으로 빨라진다는 증거는 없다. 이 측정은 작은 표본이고 전체방 처리량은 아니다.

첫 분류는 12개 중 3개를 보관했으나 필수 참여 단서 3개 중 1개를 놓쳤다. 날짜 없는 짧은 합류 요청 보존 규칙을 추가하고 캐시 규칙 버전을 4로 올렸다. 재검증에서는 5개 보관, 7개 제외, 필수 단서 3/3 보존이었다. API 930.70ms, 분류·저장 933.82ms, 같은 페이지 재분류는 API 0회와 캐시 12개, 분류 0.31ms였다. 이는 같은 작은 표본에서의 수정 후 확인이며 일반 정확도 보장이 아니다. 일부 작성자(8개)와 시각(4개)은 미확인으로 남겼다. 과거 참여 대화를 미래 확정 일정으로 만들지 않았다.

Discord는 첫 서버의 한 채널에서 참여 중 1개, 다른 활성 2개, 기타 5개 스레드가 화면에 노출됐다. 그중 기간 내 스레드 하나를 열어 별도 URL과 부모 채널을 확인했다. 최초 5개 본문만 보였지만 최근 이동과 스크롤 이후 2개가 더 로딩됐다. 이 7개를 별도 target으로 시험해 3개를 보관했고 API 367.60ms, 분류 368.13ms였다. 전체 보관 스레드 목록이 끝났다는 검증은 하지 않았다.

두 번째 허용 서버도 접근을 확인했다. 현재 화면에서 텍스트 채널 1개와 음성 채널 1개, 텍스트 채널의 활성 스레드 2개와 기타 1개를 확인했다. 숨긴 채널·목록 끝·음성 채널 텍스트 수집은 미검증이다. 서버 전체 수집 완료가 아니다. 실제 식별값과 대화 본문은 공개 보고서에 포함하지 않는다.

메시지 메뉴에서 링크/ID 복사 항목은 확인했으나 복사 후 확인한 값이 기존 클립보드와 같아 원본 ID 확보 성공으로 처리하지 않았다. 전체 확대에는 반복·수정 메시지 식별과 페이지 경계 문맥 검증이 계속 필요하다. 카톡 UI 읽기 병목도 남아 있다. 따라서 전체 수집은 보류하고 각 파일럿의 complete=false를 유지했다.

회귀 테스트 21개 통과. 개인 파일럿 자료는 사용자 앱 데이터 폴더에만 저장하고 공개 저장소·Sites에는 업로드하지 않았다. 이번 변경은 수집 로직·스킬·문서이며 웹앱 재배포 대상은 아니다.


## 착오 검토용 선별 v5 검증

일정 전용 선별을 사실·조건·정정 근거까지 확대했다. 전체 본문 저장으로 변경하지 않았다. 향후 착오 검토 탭·의견·처리완료 기능은 PLAN.md에 명시했으며 이번 작업에서 UI는 구현하지 않았다.

합성 13개 메시지에 Decisions를 실호출했다. 중복 약속·인원·장소·준비물·정정의 필수 근거 9/9 보존, 전체 11/13 보관, API 551.23ms였다. 2개는 인접 문맥으로 추가 보관됐다. 제한된 검증 표본이며 정확도 보장은 아니다.

실제 Discord 회의 스레드 한 곳에서 메시지 ID 복사 결과를 확인했다. 첫 붙여넣기는 기존 클립보드 값이었고 후속 확인에서 숫자 ID가 나왔다. 해당 서버·스레드·ID로 구성한 딥링크를 UI에서 열어 같은 메시지를 재확인했다. 링크 복사 동작은 재시도에서도 숫자 ID가 남아 있었으므로 신뢰 가능한 경로로 검증하지 않았다. 클립보드 완료 시점의 문제로 보이나 원인 전체가 확정된 것은 아니다. 호스트는 URL/ID 형식과 실제 대상 재접근을 확인해야 한다.

이 메시지 한 건을 원본 ID로 보관했다. 일정 없는 현황 주장·요청을 새 선별 기준에서 보존했고 API 266.23ms, 분류 267.00ms였다. 동일 입력 재처리는 API 0회, 메시지 총 1개로 중복 저장 없이 끝났다. 실데이터 수정·동일 문구 반복·대규모 속도와 완전성을 검증한 것은 아니다.

소프트웨어 회귀 28개 통과. 추가 검증은 멀리 떨어진 답글 원문 보존, 누락 참조의 완료 차단, 답글 연결 변경의 새 revision, 순환 참조 종료, 보존 정책 변경 시 기존 경계 무효화와 부분 실행 재시작이다. 정책 변경 전에 버린 원문은 저장 지문에서 복원할 수 없으므로 지정 범위를 UI에서 재관찰해야 한다.

전체 확대 판정: 미통과. 카톡 원본/발생 식별, 반복·수정 메시지 실검증, 전체 채널 및 활성/보관 스레드 목록 완전성, 30일 페이지 경계·재개 검증이 남았다. 전체 수집은 실행하지 않았고 개인 파일럿만 앱 데이터 폴더에 보관했다. 실제 대화·ID는 공개 보고서나 사이트에 올리지 않았다.
