# 메일·캘린더 연결

[실행 안내](../../docs/MAIL_CALENDAR_RUNBOOK.md)를 먼저 읽는다. 인증·파일럿은 구현되어 있지만 상시 증분 수집은 [계획](../../docs/MAIL_CALENDAR_PLAN.md)의 남은 작업이다. 기존 자격 증명이 있으면 값 대신 파일 존재·권한과 probe로 재사용 가능성을 확인한다.

1. 플러그인 루트, Python 3.11+ 가상환경, `requirements-mail.txt` 설치를 확인한다. 기존 OS/사용자 전역 Python 패키지를 변경하지 않는다.
2. Google은 사용자가 선택한 프로젝트의 전용 Desktop OAuth client를 사용한다. 프로젝트 생성 한도면 기존 프로젝트의 타 앱 클라이언트를 재사용하거나 이름을 바꾸지 말고 전용 client를 추가할 수 있는지 확인한다. 동의 화면 이름이 프로젝트와 공유됨을 설명한다.
3. Gmail API·Calendar API 활성화 후 `google-auth` 명령의 루프백/PKCE URL을 허용된 브라우저에서 연다. 요청 범위는 코드의 SCOPES 세 읽기 권한이다. 동의 완료와 토큰 저장 뒤 `google-probe`로 실제 API 접근을 확인한다. 브라우저 로그인만으로 연결됨을 표시하지 않는다.
4. 네이버는 메일 환경설정의 IMAP 사용, 2단계 인증, 앱 비밀번호가 필요하다. 로그인 비밀번호를 수집 설정에 저장하지 않는다. 재인증은 사용자 직접 입력으로 넘긴다. IMAP을 이미 사용 중이면 불필요하게 껐다 켜지 않는다. 앱 비밀번호는 값 출력 없이 사용자 전용 저장소로 옮기고 임시 다운로드 복사본을 정리한다.
5. Aside를 요청받았고 제공된다면 `aside-browser` 스킬 및 `aside guide repl`을 따른다. 여러 UI 단계를 이어갈 때 지속 REPL을 사용하고 동일 탭을 명시적으로 붙인다. 일회성 세션이 닫힌 후 ref/탭이 유지된다고 가정하지 않는다. 매 동작 후 새 snapshot으로 결과를 확인한다. 비밀 표시 화면의 원문 snapshot을 출력하지 않는다.
6. `naver-probe` / `google-probe` 통과 뒤 수신함 최대 10개, 기본 또는 명시 선택한 캘린더 최대 10개로 시작한다. 메일 모델 처리는 사용자의 승인 범위에서만 `--allow-external-processing`을 전달한다.
7. `gmail-pilot`, `naver-pilot`, `calendar_pilot`은 실행 결과와 반복 검증을 반환한다. 보존 근거와 확정 일정을 구별한다. 재실행 신규/변경·모델 호출 0을 확인하고 보고한다. 인증 만료·응답 크기 초과·API 오류 때 제한을 우회하거나 커서 완료를 지어내지 않는다.

## 유지해야 할 경계

- 토큰·메일 본문·실제 계정/캘린더 목록·개인 Sites 주소를 공개 패키지에 넣지 않는다. 키·토큰 파일은 0600. UI에 보이는 자격 증명을 채팅으로 붙여넣도록 요청하지 않는다.
- Gmail readonly, Calendar events/calendarlist readonly만 요청한다. 네이버 앱 비밀번호는 권한 범위가 넓으므로 클라이언트가 EXAMINE/BODY.PEEK만 수행한다. SMTP·RSVP·일정 수정은 수행하지 않는다.
- 캘린더 종일 종료 날짜는 exclusive이며 반복 예외를 별개 인스턴스로 보존한다. 다른 사람의 일정은 관찰된 범위만 표시한다.
- 메일 첨부·원격 이미지·링크를 자동으로 열지 않는다. 제목 기반 보안 제외를 완전한 민감 정보 탐지라고 주장하지 않는다.
- 수집기 추가·수정은 공통 SourceRegistry/Store/선별·일정 엔진을 유지한다. 앱별 DB/AI 파이프라인을 복제하지 않는다.
